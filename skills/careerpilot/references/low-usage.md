# Low-usage search and applications

Use when the candidate asks for low usage, a lean run, or fewer tool calls. Use the existing local helper and dashboard. The normal workflow and explicit candidate limits take precedence.

1. **Reuse saved work.** For a request to continue, inspect the saved run, ranking, and checkpoints first. Resume the same run if still open. If a comparable search is complete, offer its saved shortlist unless the candidate wants fresh listings. Check freshness before applying. Do not replay failed or uncertain submissions.
2. **Screen before opening.** On a new search, use each configured portal's visible filters and shortlist from result rows. Use observed title, location, recency, and hard requirements. Deduplicate known job IDs or canonical URLs before opening details. By default inspect up to five posting detail pages per configured portal in a lean run. A snippet is screening evidence only. Keep external-route checks for every saved primary result and mark capped or blocked coverage honestly. Do not open more pages to fill a quota.
3. **Keep inputs small.** Read only the relevant skill references and job records. Use scoped browser observations when available, such as one results section or the current form step. Keep exact labels and validation errors. Read only the metadata needed for ranking. Use the existing local ranking or daily digest instead of asking the model to rank the entire pipeline. Use supplementary public feeds only as a separate, explicit option.
4. **Prepare a small batch.** Default to preparing up to three shortlisted jobs per request, within the candidate's scope and any remaining daily capacity. Keep other matches saved. Use existing verified facts, appropriate document versions and approved field memory. Tailor documents to the specific job as required. Group jobs by exact tenant where practical and reuse an active authorized sign-in session. Budget one attempt at a recoverable form issue before deferring it with a checkpoint. Batch candidate questions and move to another eligible job if login, email verification or MFA needs the candidate.
5. **Keep reviews and permissions intact.** Do not skip document checks, evidence, pre-submit inspection, or submission authorization. Prepare only unless the candidate has explicitly authorized exact jobs or a bounded batch. Pause uncertain submissions for confirmation. End with one short list of saved, prepared, submitted and blocked jobs, plus the next candidate decision.

Example request: “Run CareerPilot in low-usage mode for data analyst jobs in Toronto. Search up to five posting details per configured portal, save verified matches, and prepare the best three for review.”
